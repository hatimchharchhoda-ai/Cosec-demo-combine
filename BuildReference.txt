SCENARIO B: Only Angular frontend changed
  Run: 3 → 4 → 8 → 9
  Skip: 1, 2, 5, 6, 7

SCENARIO C: Both backend and frontend changed
  Run: 1 → 2 → 3 → 4 → 8 → 9
  Skip: 5, 6, 7

SCENARIO D: CustomActions.cs changed (encryption logic)
  Run: 6 → 7 → 8 → 9
  Skip: 1, 2, 3, 4, 5

  Run: 5 → 6 → 7 → 8 → 9
  Skip: 1, 2, 3, 4

  Run: 8 → 9
  Skip: 1, 2, 3, 4, 5, 6, 7

SCENARIO G: First-time setup (new machine, new clone)
  Run: ALL steps 1 → 2 → (3 → 4 if needed) → 5 → 6 → 7 → 8 → 9


=============================================================================
 PATH CHANGE SUMMARY (what changed from your original commands)
=============================================================================

BEFORE (your original candle command):
  -dCustomActionsDir="CustomActions\bin\Release"

AFTER (corrected to match msbuild /p:Platform=x64 output):
  -dCustomActionsDir="CustomActions\bin\x64\Release\net472"

WHY: msbuild with /p:Platform=x64 puts output under bin\x64\Release\net472\
     (net472 = target framework folder). The old path "bin\Release" was for
     the original project which didn't specify Platform. The .CA.dll that
     WiX embeds must be found at this exact path.

BEFORE (your original MakeSfxCA command — 4 arguments):
  MakeSfxCA.exe CustomActions.CA.dll SfxCA.dll CustomActions.dll
                Microsoft.Deployment.WindowsInstaller.dll

AFTER (now 5 arguments — ConfigCrypto.dll added):
  MakeSfxCA.exe CustomActions.CA.dll SfxCA.dll CustomActions.dll
                Microsoft.Deployment.WindowsInstaller.dll
                ConfigCrypto.dll

WHY: The CA DLL now depends on ConfigCrypto.dll. MakeSfxCA bundles ALL
     dependent DLLs into the self-extracting archive so the MSI runtime
     can find them. If ConfigCrypto.dll is missing from this list, the
     installer crashes at runtime with "assembly not found".
